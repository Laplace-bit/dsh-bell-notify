🔔 dsh-bell-notify
English
DeepSeek Harness 社区插件 · MIT 开源

给 Agent 配一套可自定义的铃声通知

每个生命周期环节都有专属铃声。不用任何音频文件——所有铃声都是 Web Audio 实时合成的，还能在插件配置中换成自己的声音。

▶ 在线试听所有铃声 安装插件 GitHub 仓库 ↗

它能干什么

一个小插件，两类控制：专属铃声与自定义音源。

🎵 每个环节都有专属铃声

启动、思考、工具调用、命令完成、等待确认……每一个事件的声音都不一样，用耳朵就能分辨进度。

🎛️ 每个声音都能自己换

在设置的插件配置中试听、上传自己的音频文件、一键还原。换上的声音会记住，刷新不丢。

🎼 声音是「活」的

全部由 Web Audio 实时合成：零音频资源、包体极轻、可离线用、可随时调音高节奏。

🎧 在线试听全部铃声

与插件运行时使用同一份配方与渲染逻辑（Web Audio 振荡器实时合成，无音频文件）。音量 0.7，即默认 masterVolume。

🔊 点一下任意铃声即可解锁声音（浏览器自动播放策略）。

安装

从 DeepSeek Harness 源码仓库安装：

pnpm dsh plugin --profile bell add dsh-bell-notify

如果 PATH 上已经有 dsh：

dsh plugin --profile bell add dsh-bell-notify

启动：

pnpm dsh --profile bell

打开页面后先点一下页面任意位置（浏览器音频自动播放策略，点一次即可解锁声音），然后随便跑一个任务即可听到提示音。

卸载：

pnpm dsh plugin --profile bell remove dsh-bell-notify

🎵 每个环节的默认铃声

Agent 的一举一动都会「响一声」，而且每个环节的声音都不一样。全部可在线试听（见上）。

环节默认铃声听起来像
会话启动startup一声轻柔的上扬，像开机
开始执行click短促的一声「叮」，出发了
开始思考notify温柔的单音，进入状态
工具调用tick清脆的「哒哒」两声，金属质感
工具完成drop低低地落定，收尾
命令执行beep一声短促的哔，有终端味
命令完成rise上扬的双音，搞定
等待确认alert高频三连，叫你看一眼
本轮完成success上行大三和弦，成就感拉满
回到空闲confirm单音缓缓落下，安静了

error / failure 两个音效也内置好了，默认没启用，可在配置里按需接上。

配置

启用状态、静音、音量和每个铃声事件在 设置 → 插件 → 插件配置 → 铃声通知 中管理；下面是 profile 的常规运行参数：

选项默认说明
maxQueue8等待队列容量
maxConcurrent3同时播放的声音数（1 = 串行）
defaultCooldown1000规则默认节流窗口（毫秒）

启用状态、静音和音量持久化在当前 profile。每个事件的开关、自定义音源和文件名都持久化在浏览器本地（localStorage + IndexedDB），刷新不丢。

卡片会显示运行版本。只有 profile 确认使用 npm 包时才启用更新；link: / file: 本地安装会显示为开发版本，并保持更新禁用。

常见问题

这是 DeepSeek 官方插件吗？

不是。它是 DeepSeek Harness（dsh）的社区插件，MIT 协议开源，不属于官方发行。

为什么点了没声音？

大概率是浏览器的自动播放策略——插件首次加载后需要你先在页面上点击一次，声音才会解锁。

在哪里配置提示音和更新插件？

在 Web 设置的插件 → 插件配置 → 铃声通知中。这里可以管理启用状态、静音、音量、事件开关、自定义铃声，以及 npm 安装的更新。

自定义的声音存在哪？

文件字节存在浏览器 IndexedDB，事件到文件的映射存在 localStorage。都在本地，不会上传到任何地方。
